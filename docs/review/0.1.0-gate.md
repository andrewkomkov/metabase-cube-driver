Target: `e8e2782` on `main`, on Metabase `v0.65.2.3`, Cube `v1.8.15`, ClickHouse `26.10.3-alpine`, in compose project `mcd-review` on nettop, started from zero with `make up`. CI run 41308181904 is green on this commit, and its log has both coverage lines that the task names. The scripts and the raw results are in `dev/review/gate/`.

## State after the fixes

This part records the fixes of the findings below. The text after it is the review as it was on `e8e2782`. Raw results of these runs: `dev/review/gate/results/fix/`.

### Blockers

**B1. Fixed.** I judged the sync of private keys again and kept it, in a smaller form. A hidden field is now only the target of a foreign key, so sync reads a private key only if a join targets it. No value comes out, on dev mode or production:

- The check of the clauses reads a name reference in each stage, also in `:fields`.
- `cube.native/check-no-private-member!` reads the SQL of each query for each private member and hidden cube. On Cube in dev mode this also stops native SQL and MCP `execute_sql`, with `SELECT *` on such a table.
- The doors found a second leak that the gate did not report: a model or a second stage with a filter on the `NULL` column. `id > 100000` gave `5000`, because Cube reads that filter as a filter on the member. A later stage now shows the `NULL`, and it cannot read the column.

The foreign key stays, so `stock_items` to `warehouses.code` works. `docs/security.md` says what native SQL can reach and names dev mode as unsafe for production. The SQL API and the REST API of a Cube in dev mode, past Metabase, still read each member. The driver cannot stop that.

Results: `hidden-dev4.txt`, `hidden-prod4.txt` and `hidden-qb4.txt`, for an admin and a person with the query builder only. No door gives a value. Check: `security.private_member_gives_no_value`.

**B2. Fixed.** A `rollup_lambda` with source rows under a report time zone now reads the source, on stock Cube and with the dialect. Revenue by month on stock Cube in New York, Los Angeles, Berlin and Kolkata is equal to ClickHouse, total 319790 (`lambda3.txt`). If a filter cannot make Cube read the source, two stages do. With no report zone, a range that reads source rows can still stop with the clear message of `cube-js/cube#12285`, as before. Check: `preagg.rollup_lambda_under_a_report_zone`.

## Blockers

### B1. A hidden private key shows its values

The check of the driver, `check-no-private-key!`, reads a reference by field id. A reference by name passes it, and Cube in dev mode reads a private member.

```
POST /api/dataset {"database": 2, "type": "query", "query": {"source-table": <payments>,
  "aggregation": [["max", ["field", "id", {"base-type": "type/Integer"}]]]}}
```

Output: `[[105000.0]]`. Truth: `SELECT max(payment_id)` of the SQL of the cube is `105000`.

| Door, with the name reference | Admin, dev mode | Query builder only, dev mode | Dev mode off |
| --- | --- | --- | --- |
| `/api/dataset`: raw, max, breakout, expression, order, filter | Values | Values | Refused |
| MCP `execute_query`, `["max", {}, ["field", {"base-type": "type/Integer"}, "id"]]` | `[[105000.0]]` | `[[105000.0]]` | Refused |
| Native SQL, `SELECT MAX(id) FROM payments`, and MCP `execute_sql` | `105000` | Refused by Metabase | Refused |
| Native field filter on the key, `{{f}}` with `number/>=` | `5000` rows match, so a filter reads the value | Refused by Metabase | Not tried: the field does not exist |

Each of `payments`, `warehouses`, `promos` and `shipments` shows the same. The filter on the field id, each aggregate, expression, join, pivot, CSV, field values, parameter values, summary and x-ray stop or show no value. `dev/review/gate/results/hidden-cube.txt` has 339 lines, one for each door. `results/hidden-byname.txt` has the name references.

What the driver can do: read a name reference in the first stage on a source table as the field of that table, and apply the same check. Native SQL in dev mode is a limit that `docs/security.md` records ("Do not rely on `public: false` on a Cube in dev mode"). The driver can warn on it, and a scan can stop the name of a private key, but it stays a limit of dev mode. The task says that each value shown is a blocker, so this entry names it.

### B2. `rollup_lambda` under a report time zone on stock Cube

```
PUT /api/setting/report-timezone America/New_York
POST /api/dataset {"database": 3, "type": "query", "query": {"source-table": <lambda_sales>,
  "aggregation": [["measure", <revenue>]], "breakout": [<created_at by month>]}}
```

| Zone | Difference from ClickHouse | Total, Cube | Total, ClickHouse |
| --- | --- | --- | --- |
| None | None | 319790 | 319790 |
| `America/New_York` | June +104 | 319894 | 319790 |
| `America/Los_Angeles` | June +178 | 319968 | 319790 |
| `Asia/Kolkata` | July -183 | 319607 | 319790 |

The +104 is equal to the two rows of 2025-06-30 20:00 to 24:00 UTC, so these rows appear to come twice: from the batch and from the source. I did not read the Cube code for this cause. A filter on June or on the second quarter gives the same difference. In New York, the dialect gives the truth for each filter, and it stops the query by month with no filter. I did not run the other zones on the dialect. `Europe/Berlin` on stock stops with a clear message.

The README list and the table in `docs/query-compilation.md` do not have this entry. The nearest entry is a rollup with no `build_range_end`, which is another shape.

The driver can stop this. `probe.clj` already reads the rollups of a lambda, and the driver stops a rolling window on stock Cube under a report zone. Results: `results/lambda-stock.txt`, `results/lambda.txt`.

## Non-blockers

- **N1.** View with `default_filters`: each query that needs push-down stops, with a message about `EXTRACT` and `JOIN`. `paid_sales` net sales by month of year, by day of week, by hour of day, and by city with `starts-with` all stop. `sales` works.
- **N2.** Raw error, with no message of the driver, in 12 shapes: a custom column that reads one column twice (`case` with two branches, the plain "big, mid, low" bucket), `substring`, `regex-match-first`, `datetime-diff` from a literal, `convert-timezone`, `get-hour` under a zone, and a filter with 100 or more ids (`AST node limit`; 32 text values work).
- **N3.** `distinct` of a time stops in a zone with no clock change, such as `Asia/Kathmandu`. The message says that the clock changes.
- **N4.** The repeated hour of a clock change: Cube gives two rows with one label, `01:00:00-04:00`. Postgres labels the second row `-05:00`. The total is right. A rollup by hour joins the two rows into one.
- **N5.** A time measure has no offset in its value, where a time dimension has one. An MCP client that parses the value can read another instant. A masked measure with no group gives one row for each source row, all `-1`.
- **N6.** With dev mode off, `/v1/meta` has no private key, so sync has no hidden field and no foreign key to it: no implicit join to `warehouses`, and `users.state` stays `type/State`. So the private key work and its checks hold in dev mode only, and a production Cube syncs another model. Nothing shows a wrong number here.
- **N7.** A connection that gets `cube-user-attribute` after its first sync keeps its old field values. `/api/field/:id/values` then shows all cities to Alice. A connection with the attribute from its first sync shows none. I did not test if a rescan clears the old list. `docs/security.md` does not say this.
- **N8.** `balance_closing` by month stops, and its description says that it is the balance of the last day of a period. `balance_last_day` gives it. `rollup_lambda` after the batch stopped once and passed on the next run, with `Stream query failed`.
