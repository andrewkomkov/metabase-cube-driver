# Review before release 0.1.0

Live adversarial review on 2026-10-30, at commit `2137e78`. All queries went to the service `metabase-conformance` on `nettop.local`, through `/api/dataset` and the MCP tools. The truth is direct SQL on the demo ClickHouse.

## Result


This is the line from `make conformance`. The run exited with code 0 and did not change `conformance/features.yaml`. The checks use other query shapes, so this number does not show the defects below.

A blocker is a wrong number with no error, a leaked secret, a permission bypass, or a jar that fails to install.

## Blockers

### B1. A strict lower date bound includes the bound

- **Severity:** blocker.
- **Command:** `python3 docs/review/repro_0_1_0.py B1`
- **Query:** `created_at > '2025-03-15 05:00:00' AND created_at <= '2025-03-16 05:00:00'`, in MBQL, native SQL and MCP `execute_query`.
- **Output:** count `15`, revenue `1111.0`.
- **Truth:** count `14`, revenue `1000`.
- **Layer:** Cube SQL API. It reads the two bounds as one inclusive date range. The condition `>` alone is correct. The driver writes the literal text of the query, so it can send `>=` with the next second.

### B2. A date filter on a saved question changes the rows inside the question

- **Severity:** blocker.
- **Command:** `python3 docs/review/repro_0_1_0.py B2`
- **Query:** a saved question with revenue by month. A second stage filters on `created_at >= 2025-05-15`.
- **Output:** 8 rows. The first row is `2025-05-01, 15365.0`, a part of May. The sum is `200567.0`.
- **Truth:** 7 rows, June to December. The sum is `185202`.
- **Output for a rolling measure:** `2025-04-01, null`, `2025-05-01, 15365.0`, `2025-06-01, 27262.0`.
- **Truth for a rolling measure:** one row, `2025-06-01, 27262`.
- **Layer:** Cube pushes the outer filter below the aggregation. The SQL from the driver has the correct stages.

### B3. A rolling measure through a model gives the total of all rows

- **Severity:** blocker.
- **Command:** `python3 docs/review/repro_0_1_0.py B3`
- **Query:** a model with the column `revenue_trailing_30d`, and `sum` of that column by name. This is the form that a question on a model uses, and MCP `execute_query` with `source-card` accepts it.
- **Output:** `319790.0` with no bucket, in REST and in MCP. With a filter inside a month, by month: `27332.0`, `26498.0`, the values of the whole months.
- **Truth:** `319790` is the total of all rows, so it is not a 30 day window. The same query on the table stops with `revenue_trailing_30d is a rolling window measure`.
- **Layer:** driver. `check-rolling-measure!` reads a stored field id. A column by name has no stored field, so the check does not run.

### B4. A filter or a breakout on a measure column of a model is wrong

- **Severity:** blocker.
- **Command:** `python3 docs/review/repro_0_1_0.py B4`
- **Query:** a model with the column `revenue`, then `revenue > 150`, or a breakout on `revenue`. A person sees this column in the model.
- **Output:** with the filter, sum `319790.0` and count `5000`. The filter has no effect. With the breakout, one row: `319790.0, 5000`.
- **Truth:** sum `25896`, count `166`. The breakout has 53 groups.
- **Output, hidden column on the table:** `revenue > 100000` by status gives `completed, 2000`.
- **Truth, hidden column on the table:** no rows.
- **Layer:** driver and Cube. `restore-nested-measures` makes the inner column `MEASURE(revenue)`, and Cube then reads the outer filter as a filter on the aggregate. The check in `sql.qp/apply-top-level-clause [:cube :breakout]` also needs a stored field.

### B5. A view with two join paths to one cube uses one path for both

- **Severity:** blocker.
- **Command:** `python3 docs/review/repro_0_1_0.py B5`
- **Query:** `region_sales` by `customer_region` and `destination_region`, in REST and MCP.
- **Output:** 4 rows: `East, East, 1256`, `Midwest, Midwest, 1256`, `South, South, 1231`, `West, West, 1257`.
- **Truth:** 16 groups.
- **Layer:** Cube. The Cube REST API gives the same 4 rows. Each dimension alone is correct, and `view.several_paths` tests only that. `/v1/meta` does not show this case to the driver. The docs do not include it.

### B6. A rolling measure in native SQL gives a wrong number

- **Severity:** blocker. `measure.rolling.native_sql_limit` and `docs/query-compilation.md` already record this limit. It is a blocker under the rule for this review, because the number has no error.
- **Command:** `python3 docs/review/repro_0_1_0.py B6`
- **Query:** `SELECT MEASURE(revenue_trailing_30d) FROM orders`, in `/api/dataset` and MCP `execute_sql`.
- **Output:** `319790.0`.
- **Truth:** `319790` is the total of all rows, so it is not a window.
- **Output, filter from 04-15 by month:** `27332.0`, `26498.0`. The query with whole months gives the same values.
- **Layer:** Cube. The driver does not parse native SQL.

### B7. Native `BETWEEN` with a date text includes the whole last day

- **Severity:** blocker.
- **Command:** `python3 docs/review/repro_0_1_0.py B7`
- **Query:** `SELECT MEASURE(count) FROM orders WHERE created_at BETWEEN '2025-03-11' AND '2025-04-13'`.
- **Output:** `476`. The same query with `timestamp` literals gives `463`.
- **Truth:** `463`, with the same `BETWEEN` text on ClickHouse.
- **Layer:** Cube. A native `date` parameter has the same result: with `{{a}}` and `{{b}}`, cancelled orders gave `6100` and the truth is `5910`.

### B8. The steps in `docs/install.md` do not install the driver in the Docker image

- **Severity:** blocker for the steps as written. The jar itself loads, see below.
- **Command:**

  ```sh
  mkdir plugins
  chmod 755 plugins
  cp dev/plugins/cube.metabase-driver.jar plugins/
  # Start metabase/metabase:v0.64.3 with this directory on /plugins and MB_PLUGINS_DIR=/plugins.
  curl -s http://127.0.0.1:3302/api/session/properties
  ```

- **Output:** `engines` has 15 entries and no `cube`. The log shows `WARN plugins.impl :: Metabase cannot use the plugins directory /plugins`. Metabase then uses `/tmp`, and it starts with no error.
- **Truth:** the directory must be writable for uid 2000. After `chmod 777 plugins` and a restart, the log shows `Registered driver :cube`. `scripts/package.sh` already has this `chmod`, but `docs/install.md` and `README.md` do not tell about it.
- **Layer:** docs.

## Major

### M1. A date filter on a model or a question fails

- **Severity:** major. The query stops with an error that does not tell what to do.
- **Command:** `python3 docs/review/repro_0_1_0.py M1`
- **Query:** a model, then `sum` or `count` with `created_at >= 2025-05-10` or `between`. A dashboard date filter on a card from a model gives the same error. `MEASURE(rolling) + 1` by month gives it too.
- **Output:** `ERROR: Internal Error: Can't parse date: 'replaced_placeholder'`.
- **Truth:** sum `205548`.
- **Layer:** Cube, with bind parameters from the driver. Raw rows and relative dates on the same model work. Not proved: an inline literal can prevent this.

### M2. A week bucket with a date filter fails on the default first day of the week

- **Severity:** major. Sunday is the default in Metabase.
- **Command:** `python3 docs/review/repro_0_1_0.py M2`
- **Query:** `users` or `level_one` by week, with a date filter and the default setting. On Wednesday and Saturday, also `orders`, which has only `week_from_sunday`.
- **Output:** `ERROR: Rewrite Error: Can't parse date: 'replaced_placeholder'`. The same query with no date filter works.
- **Truth:** `docs/query-compilation.md` says that all measure types work in the week number form.
- **Layer:** the week number form of the driver, with M1.

### M3. MCP cannot count rows in a date range

- **Severity:** major. This is a common question from an agent.
- **Command:** `python3 docs/review/repro_0_1_0.py M3`
- **Query:** `execute_query` with the count measure or `count`, no breakout, and an absolute date filter.
- **Output:** `Query failed: "ERROR: Rewrite Error: Can't parse date: 'replaced_placeholder'`. Revenue alone gives `11647.0`, which is correct. Revenue and count together fail.
- **Truth:** count `154`. `/api/dataset` gives `154`.
- **Layer:** `COALESCE` from `zero-when-empty` makes this query post-processing, and Cube then fails on the parameter. Not proved: why `/api/dataset` does not fail.

### M4. A relative filter in weeks stops unless Monday is the first day

- **Severity:** major. The default setting gets a refusal for "previous 90 weeks".
- **Command:** `python3 docs/review/repro_0_1_0.py M4`
- **Output:** `Cube cannot use a week that starts on sunday here ... add a custom granularity`. The table `orders` already has this granularity, so the second part of the message does not help. With Monday, the result is `4539`.
- **Truth:** the query has a defined answer, and a filter in days or months works.
- **Layer:** driver. The relative date has no stored field, so `week-granularity` does not run.

## Minor

### m1. Segment errors are raw

- **Command:** `python3 docs/review/repro_0_1_0.py m1`
- **Output:** `Can't use OR operator with segments`, and `No field named 'users.vip'` for a segment of a joined cube.
- **Truth:** each is an error, so no number is wrong. `docs/query-compilation.md` does not list them.

### m2. `COUNT(*)` and `SUM` do not agree over a fan-out

- **Command:** `python3 docs/review/repro_0_1_0.py m2`
- **Output:** with a join from `orders` to `payments`, `COUNT(*)` is `10000` and `SUM(quantity_dim)` is `12500`.
- **Truth:** a SQL join gives `10000` and `25000`. The real total quantity is `12500`, so this is not a wrong number. The docs must tell which rule applies.

### m3. Native `COUNT(*)` on no rows gives NULL

- **Command:** `python3 docs/review/repro_0_1_0.py m3`
- **Output:** `null` in native SQL. MBQL gives `0`.
- **Truth:** `0`. The driver adds `COALESCE` only in MBQL. NULL does not look like a real count, so this is minor.

### m4. Raw errors from a rolling measure

- **Command:** `python3 docs/review/repro_0_1_0.py m4`
- **Output:** with `trailing: unbounded` for two months, `Cannot determine join keys in JOIN ON expression`. With `max` of the column, `Unknown expression or function identifier`.
- **Truth:** each is a refusal, but not a clear one. With one month, `trailing: unbounded` gives `1679`, which is correct, so `docs/query-compilation.md` and the entry `measure.rolling.unbounded` are too wide.

### m5. The table `lambda_orders` fails on each query

- **Command:** `python3 docs/review/repro_0_1_0.py m5`
- **Output:** `Missing columns: 'lambda_orders__status'`.
- **Truth:** `preagg.original_sql` records this, with status `blocked`. The cube stays public in the demo, so a person sees a table that always fails. The reason of `preagg.rollup_lambda` tells another cause.

### m6. Native SQL reads hidden members in dev mode

- **Command:** `python3 docs/review/repro_0_1_0.py m6`
- **Output:** `SELECT COUNT(*) FROM secret_audit` gives `5000`.
- **Truth:** a Cube with `CUBEJS_DEV_MODE=false` refuses this with `Table or CTE with name 'secret_audit' not found`. I tested this on a temporary container. `docs/security.md` warns about dev mode only for the JWT.

### m7. `POST /api/database/validate` returns the secret that it received

- **Command:** `python3 docs/review/repro_0_1_0.py m7`
- **Output:** HTTP 200, with `cube-api-secret-value` and `password` in clear text.
- **Truth:** this is a literal match for "must not appear", so read this entry. I rate it minor, not a leak, because only an admin can call this endpoint and the response only repeats the request body. It shows no stored value. The code is in Metabase, `warehouses_rest/api.clj`, and it applies to each driver. Each read of a stored database returned `**MetabasePass**`.

### m8. A measure column in raw rows of a model has a value

- **Command:** `python3 docs/review/repro_0_1_0.py m8`
- **Output:** through a model, order 7 shows revenue `72.0`. On the table, it shows `null`.
- **Truth:** `72` is the amount of that order, so the number is correct for this row. The two forms do not agree, and the comment on `raw-select-item` tells only the second.

### m9. `make package` fails on a Mac with no Java

- **Command:** `make package`
- **Output:** `Unable to locate a Java Runtime`, then `make: *** [package] Error 1`. No jar exists.
- **Truth:** `/usr/bin/jar` on macOS is a stub, so `command -v jar` finds it, and the script does not try `zip`. The same command on nettop works. `CONTRIBUTING.md` does not list Java.

### m10. The load check does not test the API secret

- **Command:** read `.github/scripts/load_check.py`. I did not run it, because its address is fixed to the normal Metabase.
- **Output:** it posts the key `cube-api-secret`, and its address is `127.0.0.1:3300`.
- **Truth:** the driver reads `cube-api-secret-value`. On a Cube with dev mode off, the same key gave `Cube REST API returned HTTP 403`. The check passes only because the demo Cube has dev mode on.

### m11. Other text that does not agree with the code

- **Command:** `curl` on the download URL, and the queries in the entries above.
- `docs/query-compilation.md`: "A left join from `products` to `orders` drops products". `COUNT(*)` on this join stops with `Can't find join path`. The `orders` measure works.
- `docs/query-compilation.md`: the section "What the driver stops" tells that the rolling checks work on the query builder and MCP. B3 shows a form where they do not.
- `docs/query-compilation.md`: "All measure types work in both forms". See M2.

## What I tried and could not break

All numbers below are equal to direct SQL, or the query gave a clear refusal.

- **NULLs:** I tried 22 shapes on nullable columns. They include `!=` with one and more values, `does-not-contain`, `is-empty`, booleans, a NULL group, `between`, `coalesce`, `case`, `count-where`, measures with NULLs.
- **Filtered measures and segments:** I tried `paid_revenue` with date filters and segments. I tried `not` of a segment, and a segment in `count-where`, `sum-where` and `case`.
- **Joins:** I tried a fan-out with measures of both cubes, a filter on the child, and `avg` over a fan-out. I tried distinct counts through a join, `avg_price` by status, and three cubes. I tried inner and left joins with orphan rows, and a join on columns that the model does not compare. The `CROSS JOIN` form follows the path through `shipments` or `users` that the query names.
- **Weeks:** I tried Sunday, Monday, Wednesday and Saturday. I tried a cube, a view, an inherited cube and an implicit join. I tried `day-of-week`, `week-of-year`, a filter on one week, sort and limit. The exceptions are in M2 and M4.
- **Rollups:** I tried ranges that start and end inside a month, a day and an hour. I tried month boundaries, one open bound, an empty range, relative ranges, `big_orders` and inherited rollups.
- **Rolling measures:** I tried whole buckets by day, month and quarter, and Sunday and Monday weeks. I tried `to_date`, `leading`, a status filter and breakout, and a filter on another time dimension. These gave a clear refusal: no bucket, a bound inside a bucket, a date list, an open bound, a part of a date.
- **Views and inheritance:** I tried default filters, also with a second filter and through a model. I tried view measures, `extends` on two levels, row policies, overridden members, polymorphic cubes.
- **Nested queries:** I tried aggregation of a saved question, a filter on a non-time column, `limit` in the inner query, `avg` of `avg`, a native question as a source, a metric with a breakout.
- **Native SQL:** I tried text, number, date and list parameters, and optional clauses. I tried field filters with `=`, `!=`, `contains`, a range, a month, a relative date, an excluded weekday and `between`. A quote and an injection text stay inside the value.
- **Dashboards:** filters on a cube, a view, a native card and an implicit join. A mid-bucket filter on a rolling card gives the clear refusal, and whole months give the correct number.
- **Sync:**
  - Two re-syncs keep 139 measures, 9 segments and 323 fields, with the same ids and no duplicates.
  - Edits of a table, a field, a measure, a segment and an archive survive a sync.
  - A removed member is archived. A removed dimension leaves the table. A new member appears. A new title and a new measure type reach an object that no person edited.
  - A person-edited object that comes back keeps its edit. A person-archived object stays archived. `cube-sync:reset` works.
  - A removed join clears the foreign key. A removed cube makes the table inactive and archives its objects.
  - I used a temporary file in `dev/cube/model`, and I removed it.
- **Secrets:** 147 responses have no secret, SQL password or JWT. They come from 49 endpoints as admin and as a normal user, query errors, wrong connections, and MCP tools. Of these endpoints, 11 gave 404, and some gave 403 to the normal user. A normal user gets `details: null`. A secret in the key `cube-api-secret` is also masked. The logs of Metabase and `cube` have no secret, also with trace level on the driver for 90 seconds. The log of `cube-secure` has 5 refused tokens, which `docs/security.md` tells about.
- **Permissions:** with `create-queries: no`, a normal user gets no data from `/api/dataset`, its CSV and pivot forms, field values, parameter values or cards. The same user gets no data from the MCP tools `execute_query`, `execute_sql`, `browse_data`, `search`, `get_content` and `question_write`. With access to one table only, the driver gives no data of another table through a measure, a field, a segment, a join or a view.
- **Install:** with a writable directory, the jar from `make package` registers in a new Metabase. The connection fields agree with `docs/install.md`. The first sync takes seconds. Revenue is correct. MCP works with no setting. A wrong or missing API secret on a Cube with dev mode off gives HTTP 403, and the correct one connects. The defect after a database delete in `docs/security.md` is real: search for a measure gave HTTP 500.
- **Docs that agree with the code or the live stack:** these are the error table in `docs/agents.md`, the SQL table in `docs/query-compilation.md`, the Metabase tag references, the repository settings, the status branch, the fact that the download gives 404 before a release, and the version `0.1.0` in the release pull request.

## False alarms

My first truth SQL was wrong in these cases. They are not defects.

- `sumIf` gives 0 and `SUM(CASE ...)` gives NULL for a filtered measure with no matching rows.
- A ratio of two `Decimal` values on ClickHouse truncates. With `toFloat64`, `paid_share` is correct.
- `2025-12-05~` in a date parameter means after that day, so the day is not in the range.
- A number as a filter value on `month-of-year` means milliseconds in Metabase. A date value is correct.

## Not tested

- More than `CUBEJS_DB_QUERY_LIMIT` rows in post-processing. The limit in the demo is 2 million rows, and nettop had 2 GB to 3 GB of free memory next to production services.
- `gh attestation verify` and the demo image, because no release exists.
- The latency numbers in the docs, and the search claim for a Postgres app database in `docs/agents.md`.
- Per-person data through new shapes, public links and paid Metabase features.
- The service `metabase`. I did not restart it and I did not sign in to it. Its scheduled sync can see a temporary cube if it ran during the sync test, the same as with the probe model of the suite.
